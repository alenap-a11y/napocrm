Oui, c'est tout à fait possible de créer un email send-newsletter ou tout autre type d'email supplémentaire. Avec Supabase Edge Functions et Resend, tu peux créer autant de fonctions d'envoi d'emails que tu veux.

📧 Créer une nouvelle fonction Edge pour un email personnalisé
1. Créer la fonction en local
bash
supabase functions new send-newsletter
Cela crée un dossier supabase/functions/send-newsletter/ avec un fichier index.ts.

2. Éditer le handler
Dans supabase/functions/send-newsletter/index.ts :

typescript
import { withSupabase } from 'npm:@supabase/server@^1'

const RESEND_API_KEY = Deno.env.get('RESEND_API_KEY')

const handler = async (req: Request): Promise<Response> => {
  try {
    // Récupérer les données envoyées par ton frontend
    const { email, nom, sujet, contenu, unsubscribe_token } = await req.json()

    // Appeler l'API Resend
    const res = await fetch('https://api.resend.com/emails', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${RESEND_API_KEY}`,
      },
      body: JSON.stringify({
        from: 'newsletter@ton-site.com', // Ton domaine vérifié sur Resend
        to: [email],
        subject: sujet || 'Votre newsletter',
        html: `
          <h1>Bonjour ${nom || ''} !</h1>
          <p>${contenu || 'Voici votre newsletter.'}</p>
          <p>
            <a href="https://ton-site.com/unsubscribe?token=${unsubscribe_token}">
              Se désabonner
            </a>
          </p>
        `,
      }),
    })

    const data = await res.json()
    return Response.json(data, { status: 200 })

  } catch (error) {
    return Response.json(
      { error: error.message },
      { status: 500 }
    )
  }
}

export default { fetch: withSupabase({ auth: ['user', 'secret'] }, handler) }
3. Ajouter la clé Resend dans les variables d'environnement
Crée ou modifie ton fichier .env local :

text
RESEND_API_KEY=re_xxxxxxxxxxxx
Et sur Supabase Dashboard → Edge Functions → send-newsletter → Settings → Environment Variables, ajoute la même variable.

4. Déployer la fonction
bash
supabase functions deploy send-newsletter --no-verify-jwt
5. Appeler la fonction depuis ton frontend
javascript
const { data, error } = await supabase.functions.invoke('send-newsletter', {
  headers: {
    Authorization: `Bearer ${import.meta.env.VITE_SUPABASE_SERVICE_ROLE_KEY}`
  },
  body: {
    email: 'client@email.com',
    nom: 'Jean',
    sujet: 'Newsletter du mois',
    contenu: 'Découvrez nos nouveautés...',
    unsubscribe_token: 'token_unique'
  }
})

3. "Je vais un email manuelle au début plus simple" ⚠️
Oui, c'est "plus simple" au début, mais c'est une très mauvaise pratique RGPD.

Si tu envoies un email manuellement (depuis ta boîte Gmail), tu n'as aucune trace de l'envoi, de l'ouverture, du refus, etc.

Si un utilisateur dit "Je n'ai jamais consenti" et que tu n'as pas de preuve technique (horodatage, IP, case cochée), tu perds en cas de contrôle CNIL.

👉 Solution hybride (simple et conforme) :

Dans ton admin, tu as un bouton "Envoyer l'email de validation de consentement".

Ce bouton appelle automatiquement ta fonction Edge send-consent-email.

L'email contient un lien de confirmation que l'utilisateur doit cliquer.

Quand il clique, tu enregistres la date exacte dans ta table consentements.

4. SUPPRESSION DES DONNÉES (Droit à l'effacement)
Est-ce que tu fais mal ? Question cruciale.

❌ Ce qu'il ne faut PAS faire (erreur courante) :
Supprimer définitivement la ligne de la BDD sans garder de trace.

Répondre à l'utilisateur juste par "C'est supprimé" sans preuve.

✅ Ce qu'il faut faire (bonne pratique) :
Soft delete (drapeau deleted_at à true) pendant 30 jours.

Après 30 jours, purge réelle (cron job).

Email de confirmation envoyé immédiatement après la demande (avec accusé de réception).

Conserver une trace dans une table deletion_requests (email, date, IP de la demande).

Exemple d'email :

"Bonjour, nous avons bien reçu votre demande de suppression de vos données personnelles. Elles seront définitivement effacées dans un délai de 30 jours (conformément à l'article 17 du RGPD). Vous pouvez annuler cette demande en cliquant ici [lien]."

📂 Structure de base pour tes tables SQL
sql
-- Table des consentements
CREATE TABLE consentements (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  email TEXT NOT NULL,
  nom TEXT,
  finalite TEXT NOT NULL,
  consent_texte TEXT NOT NULL,
  ip TEXT,
  user_agent TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Table des logs admin
CREATE TABLE audit_logs (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  admin_email TEXT NOT NULL,
  action TEXT NOT NULL,
  table_name TEXT NOT NULL,
  old_data JSONB,
  new_data JSONB,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Table des demandes de suppression
CREATE TABLE deletion_requests (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  email TEXT NOT NULL,
  status TEXT DEFAULT 'pending', -- pending, confirmed, deleted
  requested_at TIMESTAMPTZ DEFAULT NOW(),
  confirmed_at TIMESTAMPTZ,
  deleted_at TIMESTAMPTZ
);
